# 10. Introduction to AWS Storage Services

**AWS Storage Services: Amazon S3 & Glacier**

This section covers fundamental object storage solutions, storage vs. database distinctions, and the cost/performance characteristics of Amazon S3 storage classes.

**1. Object Storage vs. Databases**

- **Databases:** Designed to organize, index, and query structured or semi-structured data via complex queries, filtering, and transaction rules (e.g., transactional records, relational schema, user tables).
    
- **Object Storage:** Designed to hold unstructured data at vast scale (files, images, videos, logs, backups, system images) as flat objects without complex query management.
    
- **Core Difference:** Databases prioritize fast record lookups and dynamic operations; Object Storage prioritizes durability, scalability, and flat file retrieval.
    

**2. Core AWS Object Storage Overview**

- **Amazon S3 (Simple Storage Service):** Highly scalable, durable (99.999999999% / 11 9s), and secure object storage built for active, frequently accessed data (dynamic websites, media distribution, analytics pipelines).
    
- **AWS S3 Glacier:** Purpose-built, low-cost archival storage classes designed for long-term retention of rarely accessed data (compliance logs, legal archives, disaster recovery images).
    

**3. Amazon S3 Storage Classes**

|**Storage Class**|**Primary Purpose**|**Retrieval Speed**|**Key Advantage**|
|---|---|---|---|
|**S3 Standard**|Frequently accessed active data|Milliseconds|High throughput and low latency for dynamic content and web apps|
|**S3 Intelligent-Tiering**|Unknown or changing access patterns|Milliseconds|Automatically moves objects between access tiers based on usage to optimize costs without performance impact|
|**S3 Standard-IA (Infrequent Access)**|Long-lived, less frequently accessed data|Milliseconds|Lower storage cost than Standard; ideal for rapid-access backups and disaster recovery|
|**S3 Glacier Instant Retrieval**|Rarely accessed archive data needing immediate access|Milliseconds|Delivers archive-level storage pricing while preserving sub-second retrieval|
|**S3 Glacier Flexible Retrieval**|Standard archival data|Minutes to Hours|Low-cost long-term retention with configurable retrieval options (Expedited, Standard, Bulk)|
|**S3 Glacier Deep Archive**|Long-term digital preservation|12 to 48 Hours|Lowest cost storage tier in AWS; designed for compliance and multi-year data retention|

**4. Block, File & Hybrid Storage Alternatives**

- **Amazon EBS (Elastic Block Store):** Persistent block storage volumes attached directly to Amazon EC2 instances (acts like a virtual hard drive).
    
- **Amazon EFS (Elastic File System):** Fully managed, scalable POSIX-compliant network file system shared across multiple EC2 instances concurrently.
    
- **Amazon FSx:** Managed high-performance third-party file systems (e.g., FSx for Windows File Server, FSx for Lustre).
    
- **AWS Storage Gateway:** Hybrid cloud storage service enabling on-premises applications to seamlessly use AWS cloud storage.
    

**Quick Review Questions**

1. **What is the fundamental functional difference between object storage (like S3) and a database (like RDS)?**
    
    - **Answer:** Object storage holds unstructured files at scale without indexing/query management, whereas a database organizes structured data for fast indexing, relationships, and complex queries.
        
2. **Which S3 storage class automatically optimizes costs by monitoring access patterns and moving objects between access tiers?**
    
    - **Answer:** S3 Intelligent-Tiering.
        
3. **If an organization needs the lowest possible storage cost for long-term compliance archives that can tolerate a 12-to-48-hour retrieval time, which storage class should they select?**
    
    - **Answer:** S3 Glacier Deep Archive.
        
4. **How does Amazon EBS differ from Amazon S3?**
    
    - **Answer:** Amazon EBS provides block storage attached directly to EC2 virtual servers (like a local hard drive), whereas Amazon S3 is object storage accessed via network API endpoints.
