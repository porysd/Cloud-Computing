# 9. Introduction to AWS Database Services

**AWS Database Services: Relational, NoSQL, and Purpose-Built Databases**

AWS offers specialized database engines tailored to specific application workloads, avoiding "one-size-fits-all" architectural bottlenecks.

**1. Core Database Models**

- **Relational Databases (Structured):**
    
    - **Analogy:** Organized library bookshelves structured by clear rules and categories.
        
    - **Structure:** Tables with rigid schema, strict row-and-column formatting, and pre-defined foreign-key relationships.
        
    - **Strengths:** Supports complex multi-table `JOIN` queries and guarantees ACID compliance (Atomicity, Consistency, Isolation, Durability).
        
    - **Best For:** Financial platforms, ERP/CRM systems, e-commerce transaction processing.
        
- **NoSQL Databases (Non-Relational / Semi-Structured):**
    
    - **Analogy:** Dynamic magazine racks allowing rapid, flexible access to distinct items.
        
    - **Structure:** Key-value stores, JSON documents, or wide-column layouts without requiring fixed schemas.
        
    - **Strengths:** Horizontal scaling with predictable, low-latency performance at scale.
        
    - **Best For:** Real-time bidding systems, session state management, gaming leaderboards, and IoT event processing.
        

**2. Managed Primary Database Services**

- **Amazon RDS (Relational Database Service):**
    
    - Fully managed service for setting up, operating, and auto-scaling relational engines.
        
    - **Supported Engines:** MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, and Amazon Aurora (AWS's cloud-native high-performance engine).
        
- **Amazon DynamoDB (NoSQL Key-Value Store):**
    
    - Fully managed, serverless key-value and document database delivering single-digit millisecond latency at scale.
        
    - Offers automatic partition scaling and global replication (Global Tables).
        

**3. Purpose-Built Specialized AWS Databases**

|**Database Service**|**Type / Category**|**Primary Use Case**|
|---|---|---|
|**Amazon ElastiCache**|In-Memory (Redis / Memcached)|Ultra-fast caching, session storage, and microsecond response times|
|**Amazon DocumentDB**|Document Store (MongoDB compatible)|Semi-structured content management, catalogs, and user profiles|
|**Amazon Neptune**|Graph Database|Navigating dense, interconnected data (social networks, fraud detection)|
|**Amazon Timestream**|Time-Series Database|Tracking time-stamped telemetry data, IoT logs, and operational metrics|

> **Note on Amazon QLDB:** Amazon Quantum Ledger Database was formally deprecated by AWS on July 31, 2025. Immutable audit logging workloads are now directed to Amazon Aurora PostgreSQL (via log/audit extensions) or application-level history mechanisms.

**4. Data Migration: AWS DMS**

- **AWS Database Migration Service (DMS):**
    
    - Facilitates database migrations to AWS with minimal downtime, keeping source databases operational during replication.
        
    - **Homogeneous Migration:** Same engine to same engine (e.g., On-prem PostgreSQL → Amazon RDS PostgreSQL).
        
    - **Heterogeneous Migration:** Different source and target engines (e.g., Oracle → Amazon Aurora MySQL) using the AWS Schema Conversion Tool (SCT).
        

**Quick Review Questions**

1. **What is the primary difference in structure and query capabilities between Amazon RDS and Amazon DynamoDB?**
    
    - **Answer:** RDS is relational, using fixed tables/schemas and complex SQL `JOIN` queries, whereas DynamoDB is a NoSQL key-value/document store designed for fast, single-digit millisecond queries without relational schema constraints.
        
2. **Which AWS database service should you choose if your application requires caching frequent queries to achieve microsecond latency?**
    
    - **Answer:** Amazon ElastiCache.
        
3. **What is the difference between homogeneous and heterogeneous database migrations in AWS DMS?**
    
    - **Answer:** Homogeneous migrations move data between identical database engines (e.g., MySQL to MySQL), while heterogeneous migrations convert schemas and migrate data between different engines (e.g., Oracle to Aurora).
        
4. **If an application models complex relationships between users, such as a social media graph or fraud detection network, which AWS database is best suited?**
    
    - **Answer:** Amazon Neptune.
