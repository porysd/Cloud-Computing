# 8. Introduction to AWS Compute Services

**AWS Compute Services: Server-Based vs. Serverless**

AWS Compute provides the processing power required to host applications, run business logic, and handle dynamic traffic workloads at scale.

**1. Core Computing Models**

- **Server-Based Computing (Infrastructure as Service - IaaS):**
    
    - **Analogy:** Owning a car—always available, highly customizable, but requires ongoing maintenance and operational oversight.
        
    - **Operational Model:** Dedicated virtual instances provisioned 24/7.
        
    - **Billing:** Billed continuously for instance uptime (per second/hour), regardless of whether the server is actively processing requests or sitting idle.
        
    - **Best For:** Long-running services, monolithic web applications, legacy software, and workloads requiring custom OS settings or deep root access.
        
- **Serverless Computing (Function as a Service - FaaS):**
    
    - **Analogy:** Hailing a taxi—available on demand, handles transportation automatically, and vanishes when the ride ends.
        
    - **Operational Model:** Event-driven execution where AWS manages infrastructure provisioning, OS patching, auto-scaling, and capacity allocation.
        
    - **Billing:** Billed purely on request volume and exact execution duration (measured in milliseconds). Zero cost when idle.
        
    - **Best For:** Microservices, real-time file processing, automated background jobs, and unpredictable or bursty traffic patterns.
        

**2. Direct Comparison: Amazon EC2 vs. AWS Lambda**

|**Feature**|**Amazon EC2**|**AWS Lambda**|
|---|---|---|
|**Paradigm**|Server-Based (Virtual Machines)|Serverless (Event-Driven Functions)|
|**Control Level**|High (Choice of OS, storage, networking)|Low (Focus strictly on application code)|
|**Scaling**|Auto Scaling groups (boots new VMs)|Automatic, instant sub-second scaling per request|
|**State**|Stateful (persistent local storage/drives)|Ephemeral / Stateless|
|**Pricing Model**|Paid per hour/second of uptime|Paid per execution request & duration (ms)|
|**Typical Use Cases**|Full websites, databases, big data analytics|File processing, API backends, automated triggers|

**3. Specialized Compute Offerings**

Beyond EC2 and Lambda, AWS offers additional compute architectures across two main categories:

- **Container Services:**
    
    - **Amazon ECS / EKS:** Manage containerized applications using Docker or Kubernetes for microservice orchestration across managed clusters.
        
    - **AWS Fargate:** Serverless compute engine for containers that runs ECS/EKS tasks without requiring instance management.
        
- **Edge & Hybrid Compute:**
    
    - **AWS Outposts & Local Zones:** Deploys AWS infrastructure and services to physical on-premises facilities or specific local geographic areas to meet ultra-low latency demands.
        

**Quick Review Questions**

1. **What is the primary operational difference between Amazon EC2 and AWS Lambda?**
    
    - **Answer:** EC2 requires managing full virtual servers continuously (server-based), whereas Lambda runs application code automatically in response to triggers without server management (serverless).
        
2. **In terms of pricing, why can Lambda be more cost-effective for unpredictable workloads than EC2?**
    
    - **Answer:** Lambda charges only for the exact execution time (in milliseconds) when triggered and $0 when idle, while EC2 incurs continuous charges while the instance is running.
        
3. **What serverless container engine allows you to run containers without managing underlying EC2 instances?**
    
    - **Answer:** AWS Fargate.
        
4. **Which compute model gives developers maximum control over the operating system, storage configuration, and root environments?**
    
    - **Answer:** Server-based compute via Amazon EC2.
