# 7. Define the AWS Global Architecture

**AWS Global Infrastructure & Architecture**

This chapter covers how AWS structures its physical footprint worldwide—from localized data centers to high-availability clusters and global edge caching.

**1. Architectural Components**

- **AWS Regions:**
    
    - **Definition:** Fully isolated, separate geographic areas around the world containing clusters of data centers.
        
    - **Key Considerations:** Region selection is guided by **user proximity (latency)**, **legal/compliance requirements (data residency)**, **service availability**, and **cost variations**.
        
- **Data Centers:**
    
    - **Definition:** The physical facilities housing compute servers, storage arrays, and networking equipment.
        
    - **Features:** Built with independent power, uninterruptible power supplies (UPS), cooling infrastructure, and physical security measures to protect continuous operations.
        
- **Availability Zones (AZs):**
    
    - **Definition:** One or more discrete data centers within a Region, physically separated by meaningful distances to mitigate shared disaster risks.
        
    - **Interconnection:** Connected to each other via high-bandwidth, ultra-low-latency dedicated metro fiber.
        
    - **Fault Isolation:** Each AZ features independent power, cooling, and network links. A disruption in one AZ does not impact adjacent AZs within the same Region.
        
- **Edge Locations & Points of Presence:**
    
    - **Definition:** Global sites distinct from main Regions that cache static and dynamic content closer to end-users.
        
    - **Core Service Integration:** Utilized by **Amazon CloudFront** (CDN), **Amazon Route 53** (DNS), and **AWS Global Accelerator** to drastically reduce latency and lower packet delivery times.
        

**2. High Availability Architecture in Action**

To maintain uptime during high-traffic events (such as Black Friday sales spikes), AWS components work together across multiple layers:

|**Layer**|**Component**|**Core Responsibility**|
|---|---|---|
|**Edge Layer**|Edge Locations (CloudFront)|Caches images, videos, and static files locally to handle initial incoming requests with zero backend lag.|
|**Compute / Storage Layer**|Data Centers|Executes business logic, application code, and database writes on underlying physical hardware.|
|**Resilience Layer**|Availability Zones|Automatically routes traffic to redundant healthy instances in parallel AZs if a localized outage occurs.|

**Quick Review Questions**

1. **What is the primary architectural difference between an AWS Region and an Availability Zone (AZ)?**
    
    - **Answer:** An AWS Region is an entire geographic area, whereas an Availability Zone consists of one or more discrete, physically separated data centers _within_ that Region.
        
2. **How do Edge Locations help improve user experience for globally distributed applications?**
    
    - **Answer:** By caching content locally near the end-user, Edge Locations minimize data latency and speed up download and page load times.
        
3. **Why are Availability Zones physically separated by distance within a Region?**
    
    - **Answer:** Physical separation ensures that localized physical disasters (e.g., power grid failure, flooding) affect only one AZ, allowing the remaining AZs to maintain application availability.
        
4. **Which AWS content delivery service directly leverages Edge Locations?**
    
    - **Answer:** Amazon CloudFront.
