# 4. Overview of Azure Compute - Part 1

This section explores foundational compute concepts—such as serverless vs. stateless architectures—and covers three primary Azure Compute offerings: **Azure Virtual Machines**, **Azure App Service**, and **Azure Functions**.

**1. Architectural Concepts: Serverless vs. Stateless**

- **Serverless Computing:** Abstracts physical and virtual infrastructure from the developer. Servers still exist, but allocation, provisioning, and scaling are fully managed by Azure. Developers focus strictly on application code.
    
- **Stateless Computing:** Applications or execution environments that do not retain state or persistent data across transactions. Every incoming request is processed independently without memory of past interactions (analogous to a vending machine transaction).
    

**2. Core Azure Compute Services**

|Service|Hosting Model|Degree of Control|Typical Use Case|
|---|---|---|---|
|**Azure Virtual Machines**|Infrastructure as a Service (IaaS)|**Maximum Control:** Full control over operating system (Windows/Linux), custom runtime versions, and software patches.|Legacy applications requiring custom OS configurations or specific software dependency versions.|
|**Azure App Service**|Platform as a Service (PaaS)|**Balanced:** Azure handles OS patching and runtime maintenance while developers deploy web apps and APIs.|Web applications, REST APIs, and mobile backends requiring continuous integration/deployment (CI/CD).|
|**Azure Functions**|Serverless / Function as a Service (FaaS)|**Minimal Infrastructure:** Event-driven execution model where code runs strictly in response to triggers.|Background processing, database change streams, webhooks, and sporadic tasks.|

**3. Deep Dive into Key Compute Services**

### Azure Virtual Machines (IaaS)

Provides virtualized computing hardware for maximum customization. Allows teams to select specific operating systems, configure networking, and isolate applications that depend on specific legacy software dependencies.

### Azure App Service (PaaS)

Fully managed platform for hosting web applications and APIs. Supports continuous deployment via native integrations with GitHub, Bitbucket, and Azure Repos, allowing developers to push code updates automatically without server maintenance.

### Azure Functions (Serverless / FaaS)

Event-driven compute platform that automatically scales based on demand. Code executes only when triggered by specific events (such as incoming HTTP requests, database modifications, or message queue events).

**Quick Review Questions**

1. **What is the fundamental difference between serverless computing and stateless computing?**
    
    - **Answer:** Serverless abstracts server management and auto-scales infrastructure, whereas stateless means an application does not retain data or memory from previous transactions.
        
2. **Which Azure Compute service provides maximum operational control, including the choice and configuration of the underlying operating system?**
    
    - **Answer:** Azure Virtual Machines (IaaS).
        
3. **If a developer wants to host a web application with CI/CD integration without managing OS updates, which service should they select?**
    
    - **Answer:** Azure App Service (PaaS).
        
4. **How does Azure Functions execute code, and what triggers its execution?**
    
    - **Answer:** It executes serverless code in response to specific events, such as HTTP requests, database updates, or message queue notifications.
