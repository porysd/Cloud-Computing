# 6. Azure Storage Services

**Azure Storage Services & Data Redundancy**

This section explores Azure's storage tiers, core storage products, backup/recovery mechanisms, and data redundancy strategies.

**1. Azure Access Tiers**

Azure Storage provides online and offline access tiers optimized for access frequency and storage cost tradeoffs:

- **Hot Tier:** Highest storage cost, lowest access cost. Designed for frequently accessed active data (e.g., live website media).
    
- **Cool Tier:** Lower storage cost, higher access cost. Intended for infrequently accessed data stored for at least 30 days.
    
- **Cold Tier:** Optimized for rarely accessed data requiring immediate online access with a 90-day minimum retention period.
    
- **Archive Tier:** Lowest storage cost, highest access cost. An **offline** tier for long-term retention (180+ days) requiring several hours to rehydrate data before reading.
    

> Lifecycle management rules can automatically shift objects between access tiers over time based on last modified or access timestamps.

**2. Core Storage Offerings**

|**Offering**|**Target Data Type**|**Primary Use Cases**|
|---|---|---|
|**Azure Blob Storage**|Unstructured (text, binary, video, images)|Massively scalable object storage accessed globally over HTTP/HTTPS.|
|**Azure Data Lake Storage (ADLS)**|Structured, semi-structured, unstructured|High-performance big data analytics built on top of Blob Storage with a hierarchical namespace.|
|**Azure Files**|Shared files (SMB/NFS protocols)|Fully managed cloud file shares that integrate seamlessly with existing legacy and enterprise OS applications.|
|**Azure Backup**|Server images & volume backups|Simple, integrated backup and disaster recovery for both on-premises and cloud workloads.|

**3. Data Redundancy Options**

Azure automatically duplicates stored data across infrastructure to ensure high availability and disaster tolerance:

```
[ LRS (Locally Redundant) ]    Copies 3x inside a SINGLE datacenter in one region.
[ ZRS (Zone-Redundant) ]       Copies 3x across 3 Availability Zones within ONE region.
[ GRS (Geo-Redundant) ]        Copies 3x locally + replicates asynchronously to a SECOND paired region.
```

- **Locally Redundant Storage (LRS):** Replicates data 3 times within a single physical datacenter in a primary region. Protects against localized hardware failures at a low cost.
    
- **Zone-Redundant Storage (ZRS):** Replicates data across three physical Availability Zones in the primary region. Protects against datacenter-level outages.
    
- **Geo-Redundant Storage (GRS):** Replicates data 3 times in the primary region (LRS style) and then asynchronously mirrors it to a secondary geographic region hundreds of miles away. Protects against total regional disasters.
    

**Quick Review Questions**

1. **Which Azure access tier offers the lowest storage cost but requires several hours of data rehydration before files can be read?**
    
    - **Answer:** The Archive Tier.
        
2. **What architectural feature distinguishes Azure Data Lake Storage from standard Azure Blob Storage when handling large-scale analytics data?**
    
    - **Answer:** Data Lake Storage adds a hierarchical file system namespace on top of Blob Storage for fast analytics file processing.
        
3. **How many copies of your data does Locally Redundant Storage (LRS) maintain, and where are they stored?**
    
    - **Answer:** It maintains 3 copies within a single datacenter in the primary region.
        
4. **Which redundancy option provides cross-region disaster recovery protection by asynchronously replicating data to a secondary region?**
    
    - **Answer:** Geo-Redundant Storage (GRS).
